## 1. 已澄清、可直接落地的硬结论

以下结论已写进模块文档，开发时直接采用，**不回头问**：

1. **阶段即卷**：玩家看到的「第 N 卷」= 大阶段顺序，不单独配置卷名。
2. **境界突破在小游戏里**：采用小游戏形式（剧情设定第 8 节已确认）。
3. **寿元 = 健康度（HP）**：战斗失败扣寿元，归零重生；与年龄无关。
4. **灵石收支无公式**：= 所有已配置「灵石变化」字段的累加（获得即用、花了就减）。
5. **临时状态 = 数组存储**：每项 `{属性, 变化值, 剩余节点数}`，叠加、单独到期、重生清空。
6. **炼丹是小游戏之一**：其「灵材」是小游戏内部输入，不进物品配置。
7. **本世评分仅由「战斗」+「小游戏」产生**：普通剧情事件节点（选项按钮）不加不减本世评分。

## 2. 待确认项与「是否阻塞开发」的判定

结论：**全部待确认项均不硬阻塞开发**，可先按合理默认值「带着开发」，等朋友回复再回填。逐条处理方式：

| 编号 | 疑问（用界面文字指代） | 阻塞？ | 带着开发的默认值 |
|---|---|---|---|
| Q1 | 角色页「境界进度 1200/3000」是啥 / 突破要不要进度条 | 否 | 角色页先画进度条占位（值传 0 或隐藏），突破暂按「数字等级」触发，不依赖进度 |
| Q2 | 「分配属性点」入口在哪 | 否（技术已明确） | 数据模型先建：每种属性点独立字段、加权值；入口先放「角色页-突破结算后」，样式后调 |
| Q3 | 本世结算「评级」怎么生成 | 否 | 先复用「通关评分档位」名称作评级；独立评级规则后补 |
| Q4 | 本世结算「事件扣分 -5」从哪来 | 否（已澄清普通节点不加） | 普通节点评分变化字段**不建**；-5 待朋友确认是否特殊事件 |
| Q5 | 转盘「加码（30 灵石 / 升 1 档）」对不对 | 否（小游戏最后做） | 前期用模拟界面，不接真实数值；正式配置时再用 |
| Q6 | 气运对应什么补差区间 | 否 | 先按 `补差上限 = 气运值（0~100）` 实现，取整细节后调 |
| Q7 | 按钮「随机权重」怎么抽 | 否 | 先实现「过滤不满足→必现占坑→按权重轮盘赌抽补足」基础版；同按钮不重复出现 |
| Q9 | 年龄是否「过节点自动增长」 | 否 | 创建角色只定昵称+性别；年龄留空/写死初值 18，不参与逻辑 |
| Q8/10~14 | 内部待定（第三属性、小游戏正式配置、寿元叠加、评分边界、属性点技术细节） | 否 | 均按文档各自默认值带着开发，不阻塞 |

→ 所以**所有模块现在都能动手**；下文的「分期」是按依赖关系排的优先级，不是「能不能做」。

## 3. 可立即开工的模块（按优先级分期）

### P0 · 基础数据层（无依赖，做扎实）
后台配置，其他模块全部引用：
- **属性配置界面**：基础属性（根骨/精怪/魅力/体魄/财富）+ 特殊属性（气运/投掷次数/第三待定）。
- **物品配置界面**：遗物（可永久保留、不可售、不可重复获得）/ 消耗品（仅能购买、可使用）/ 剧情道具（消耗在按钮里定义）。
- **天赋配置界面**：品质（名称+颜色可配）、开局配置（初始等级/属性/寿元/灵石/天赋点）、通关评分档位、可选数量上限。

### P1 · 角色系统（依赖 P0）
- 玩家端「角色」页：玉牌（境界/年龄占位）、境界、寿元（血格）、灵石、基础+特殊属性、临时状态数组、已生效天赋。
- 玩家端「创建角色」白描页：填昵称 + 选性别（年龄留空）。

### P2 · 节点 / 剧情流（核心，依赖 P0 + 物品）
- **按钮配置界面**：文字/类型/必现/权重/一次性 + 开启条件 + 点击消耗 + 点击效果。
- **剧情节点配置界面**：串按钮 + 战斗 + 小游戏入口；战斗配判定属性/门槛/气运补差/投掷次数 + 成功/失败（失败可配广告续命）。
- 玩家端「剧情」页：资源条 + 节点正文 + 最多 3 选项（服务端过滤+随机补足，结果存服务端）。
- 玩家端「战斗结算」页：成功/失败态、属性变化、评分明细、获得遗物、解锁 CG。

### P3 · 经济 / 收集（依赖 物品）
- **商品配置界面**：引用物品表，配价格/上架/重复购买/每世上限（商店本身不单独建）。
- 玩家端「商店」页：节点通关后开，按灵石买，唯一遗物不可重复买。
- 玩家端「背包」页：遗物/消耗品/剧情道具三 Tab，消耗品可「使用」。
- **CG 配置界面** + 玩家端「CG 图鉴」页：已解锁回看、未解锁显「?」。

### P4 · 境界 / 突破（依赖 属性 + 天赋）
- **境界配置界面**：等级→境界名→突破寿元/可分配属性点/单项上限。
- 突破（小游戏形式）：先接**模拟小游戏**（点按钮给结果），属性点分配入口后续补（见 Q2）。

### P5 · 局外成长 / 重生（依赖 天赋 + 本世结算）
- 玩家端「本世结算」页：评级（先复用评分档位名）、本世评分、奖励天赋点、从本世遗物选 1 件永久保留、重生。
- 玩家端「天赋」页：花天赋点选天赋，有已选上限；品质决定点数消耗。

### P6 · 小游戏（最后，依赖 全部）
- 转盘 / 答题 / 炼丹：前期用简陋**模拟界面**（第一档/第二档/第三档/失败按钮），正式配置模块（题目、分区概率、配方+炸炉）最后再议。

### 贯穿项
- `bhgt-admin`：左侧一溜菜单 + 各配置页壳（MainLayout 已在代码层），随 P0~P5 逐页填充。
- **游戏基本信息配置界面**（新增白描 mock）：游戏名/副标题/版本，硬编码落库，随时可做。

## 4. 建议开发顺序总表

| 阶段 | 模块（玩家端 / 后台） | 依赖 | 带着开发的默认值 | 完成标志 |
|---|---|---|---|---|
| **P0** | 属性 / 物品 / 天赋配置 | 无 | 第三特殊属性、悟性先留「待定」字段 | 三张配置界面可增删改查，被下游引用 |
| **P1** | 角色页 / 创建角色 | P0 | 年龄留空，不参与逻辑 | 角色数据能读能展示；创建只定昵称+性别 |
| **P2** | 按钮+节点配置 / 剧情页 / 战斗结算 | P0、物品 | 气运=气运值补差；按钮随机=轮盘赌基础版；普通节点不加减评分 | 能跑通「节点→选项→战斗→结算」主链路 |
| **P3** | 商品+商店 / 背包 / CG配置+图鉴 | 物品 | 商店不单独建，通关展示全部上架 | 经济闭环（买/用/图鉴）可玩 |
| **P4** | 境界配置 / 突破（模拟） | 属性、天赋 | 突破先接模拟小游戏；属性点分配入口后补 | 境界能升；突破能触发并给结果 |
| **P5** | 本世结算 / 天赋页 | 天赋、结算 | 评级先复用评分档位名 | 重生闭环（选遗物/天赋点/重生）可玩 |
| **P6** | 转盘/答题/炼丹（正式） | 全部 | 前期模拟界面；正式配置最后做 | 三种小游戏按真实规则可玩 |

## 5. 依赖关系（文字版）

```
P0 基础数据（属性/物品/天赋）
   ├─> P1 角色系统
   ├─> P2 节点流（按钮+节点+剧情+战斗）──> 主链路
   ├─> P3 经济（商品+商店+背包+CG）       基础数据/物品
   ├─> P4 境界（境界配置+突破）          属性+天赋
   └─> P5 局外成长（本世结算+天赋页）    天赋+结算
P6 小游戏 ──> 依赖以上全部，放最后
```

最短关键路径（先让游戏能跑起来）：**P0 → P2 → P5**（属性/物品/天赋 → 节点战斗主链路 → 重生闭环）。这条链通了，就有可玩 Demo；P1/P3/P4 是并行填充，P6 最后。

朋友每回一条疑问（Q1~Q7、Q9），流程：
1. 把结论写回 `疑问讨论_2026-08-05_第一版.md` 对应条目，标注「已确认 + 结论」；
2. 同步修正 `player-modules.md` / `admin-modules.md` 里受影响的描述；
3. 回填对应阶段「带着开发的默认值」，不阻塞其他阶段。

内部待定项（Q8、Q10~Q14）不打扰朋友，按文档默认值继续，待相关阶段临近收尾时再内部拍板。
