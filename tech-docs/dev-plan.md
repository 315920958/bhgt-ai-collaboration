## 0. 三项目总览与依赖方向

| 项目 | 角色 | 依赖 |
|---|---|---|
| **bhgt-server** | 数据 + 逻辑中枢（Mongoose 模型、战斗判定、评分、按钮随机、重生、临时状态、灵石收支、境界突破、各配置 CRUD 接口、玩家存档接口） | 无（最先动，定义接口契约） |
| **bhgt-admin** | 后台配置界面（左侧菜单 + 各配置页壳），把 server 的接口可视化 | 依赖 server 的配置 CRUD 接口就绪 |
| **bhgt-h5-client** | 玩家端页面（剧情/角色/商店/战斗结算/本世结算/天赋/CG）+ 小游戏 | 依赖 server 的玩家存档与节点/战斗接口就绪 |

**跨项目顺序原则**：server 先定义数据模型与接口契约 → admin 与 h5 并行对接。最短可玩 Demo 路径 = `server 基础数据+节点战斗+重生` + `h5 主链路`；admin 初期可手动插库，但建议同步做基础数据配置页以便可视化。

## 1. 已澄清、可直接落地的硬结论

1. **阶段即卷**：玩家看到的「第 N 卷」= 大阶段顺序，不单独配置卷名。
2. **境界突破在小游戏里**：采用小游戏形式（剧情设定第 8 节已确认）。
3. **寿元 = 健康度（HP）**：战斗失败扣寿元，归零重生；与年龄无关。
4. **灵石收支无公式**：= 所有已配置「灵石变化」字段的累加。
5. **临时状态 = 数组存储**：每项 `{属性, 变化值, 剩余节点数}`，叠加、单独到期、重生清空。
6. **炼丹是小游戏之一**：其「灵材」是小游戏内部输入，不进物品配置。
7. **本世评分仅由「战斗」+「小游戏」产生**：普通剧情事件节点（选项按钮）不加不减本世评分。

## 2. 待确认项与「是否阻塞开发」的判定

全部待确认项（Q1~Q7、Q9 需问朋友；Q8、Q10~Q14 内部待定）**均不硬阻塞开发**，可先按合理默认值「带着开发」，等回复再回填。逐条处理方式：

| 编号 | 疑问（界面文字指代） | 影响项目 | 带着开发的默认值 |
|---|---|---|---|
| Q1 | 角色页「境界进度 1200/3000」是啥 / 突破要不要进度条 | h5 角色页、server 境界 | 进度条先占位（值 0 或隐藏）；突破按数字等级触发，不依赖进度 |
| Q2 | 「分配属性点」入口在哪 | h5 角色页、server 突破 | 数据模型先建：每种属性点独立字段、加权值；入口先放角色页-突破结算后，样式后调 |
| Q3 | 本世结算「评级」怎么生成 | h5 本世结算、server 评分 | 先复用「通关评分档位」名称作评级；独立规则后补 |
| Q4 | 本世结算「事件扣分 -5」从哪来 | server 评分、h5 结算 | 普通节点评分变化字段**不建**；-5 待确认是否特殊事件 |
| Q5 | 转盘「加码（30 灵石/升 1 档）」对不对 | h5 小游戏、server 小游戏 | 前期模拟界面，不接真实数值；正式配置时再用 |
| Q6 | 气运对应什么补差区间 | server 战斗判定 | 先按 `补差上限 = 气运值（0~100）` 实现，取整细节后调 |
| Q7 | 按钮「随机权重」怎么抽 | server 节点逻辑、admin 按钮配置 | 先「过滤不满足→必现占坑→权重轮盘赌补足」；同按钮不重复出现 |
| Q9 | 年龄是否「过节点自动增长」 | h5 创建角色/角色页 | 创建只定昵称+性别；年龄留空/写死 18，不参与逻辑 |
| Q8/10~14 | 内部待定（第三属性、小游戏正式配置、寿元叠加、评分边界、属性点技术） | 三项目相关处 | 按文档各自默认值带着开发，不阻塞 |

## 3. 项目一：bhgt-server（服务端，最先动）

> 已有基础：基础设施层（CORS/Auth/响应格式化/异常/MESSAGE_BODY）、AES-GCM 认证、三表 schema（sys.users/tt.users/game.users）、dev-login/admin-login/taptap-login 骨架、Mongoose 连接。

### S0 基础设施补齐（轻量）
- 错误码表（`error-code.md` 已定义）接入各异常；
- 配置项（`@nestjs/config` 多 env）齐全：DB_NAME、AUTH_AES_KEY、token 过期。

### S1 基础数据模型 + 配置 CRUD（无依赖，做扎实）
- Mongoose schema：**属性**（基础+特殊）、**物品**（遗物/消耗品/剧情道具三类）、**天赋**（品质/开局配置/评分档位/可选上限）。
- 对应模块的 CRUD 接口 + DTO（供 admin 调用）：`/admin/attributes`、`/admin/items`、`/admin/talents`。
- 默认值：第三特殊属性、悟性先留「待定」字段。

### S2 节点与战斗核心逻辑（依赖 S1）
- 节点 schema + 接口（`/nodes`）；按钮 schema + 接口（`/admin/buttons`）。
- **核心算法（纯 TS 模块，与 UI 解耦）**：
  - 按钮筛选：过滤不满足开启条件 → 必现占坑 → 权重轮盘赌补足（Q7 默认值）。
  - 战斗判定：属性全过门槛→成功；不足→气运补差（上限=气运值，Q6 默认值）→投掷次数重试。
  - 评分：Σ 超额属性点 → 档位 → 档位分值 × 全局乘数（普通节点不加评分，Q4）。
  - 临时状态：数组 `{属性,变化值,剩余节点数}`，叠加、单独到期、重生清空。
  - 灵石收支：各配置灵石变化字段累加（无公式）。

### S3 境界与突破（依赖 S1）
- 境界 schema + 接口（`/admin/realms`）：等级→境界名→突破寿元/可分配属性点/单项上限。
- 突破发放属性点：每种属性点独立字段、加权值（Q2 数据模型先建）；突破以「小游戏形式」触发，前期 server 返回模拟档位。
- 重生逻辑：本世结算 → 选 1 遗物永久保留 → 清临时状态 → 回起始节点，保留 CG/永久遗物/天赋点。

### S4 玩家存档与游戏接口（依赖 S2/S3）
- game.users 扩展字段：昵称、性别、年龄（留空）、境界、寿元、灵石、属性、临时状态数组、已生效天赋、CG 解锁列表。
- 接口：`/game/start`（新游戏，读开局配置）、`/game/node`（取节点+筛选后按钮，结果存服务端）、`/game/battle`（战斗判定+结算）、`/game/settle`（本世结算+重生）、`/game/cg`、`/game/role`。

### S5 小游戏接口（最后，依赖全部）
- 前期：节点/突破调用的小游戏返回模拟档位（第一档/第二档/第三档/失败）。
- 正式：转盘（分区概率+加码）、答题（题目/计分）、炼丹（配方+炸炉）配置与判定，放最后做。

## 4. 项目二：bhgt-admin（后台配置，依赖 server S1+）

> 已有基础：Vue3 + 路由 + MainLayout（左侧菜单壳）+ 请求层（axios 拦截器拆 MESSAGE_BODY）+ Element Plus。

### A0 框架填充
- 左侧菜单接齐：属性/物品/天赋/按钮/节点/商品/CG/境界/游戏信息（对应 server 各配置模块）；路由守卫已有。

### A1 基础数据配置页（依赖 server S1）
- 属性配置页、物品配置页（三类 Tab）、天赋配置页（多 Tab：列表/品质/开局/评分档位/可选上限）。

### A2 节点流配置页（依赖 server S2）
- 按钮配置页（四区：基础/开启条件/点击消耗/点击效果）、剧情节点配置页（串按钮+战斗+小游戏入口；战斗判定/门槛/气运补差/投掷次数；成功失败文案与效果；广告续命）。

### A3 经济与收集配置页（依赖 server S1/S4）
- 商品配置页（引用物品、价格/上架/重复购买/每世上限）、CG 配置页、游戏基本信息配置页（游戏名/副标题/版本，硬编码落库）。

### A4 境界配置页（依赖 server S3）
- 境界配置页（等级→境界名→突破寿元/属性点/上限）。

> 小游戏正式配置页（转盘/答题/炼丹）放最后，对应 server S5。

## 5. 项目三：bhgt-h5-client（玩家端，依赖 server S2+）

> 已有基础：React + HashRouter + MobileLayout（底部 TabBar 壳）+ 请求层 + antd-mobile + dev 万能登录/TapTap 骨架。

### H0 框架（已有壳，接路由）
- 首页 / 剧情 / 角色 / 背包 / 商店 / 战斗结算 / 本世结算 / 天赋 / CG 九个页面路由 + TabBar。

### H1 创建角色 + 角色页（依赖 server S4）
- 创建角色页（填昵称+选性别，年龄留空）；角色页（玉牌/境界/寿元血格/灵石/属性/临时状态数组/已生效天赋；进度条先占位 Q1）。

### H2 剧情 + 战斗结算主链路（依赖 server S2/S4）——核心
- 剧情页（资源条+节点正文+≤3 选项，结果存服务端）；战斗结算页（成功/失败态、属性变化、评分明细、获得遗物、解锁 CG）。

### H3 经济与收集（依赖 server S4）
- 商店页（通关后开，按灵石买，唯一遗物不可重复买）；背包页（三类 Tab，消耗品可「使用」）；CG 图鉴页（已解锁回看、未解锁显「?」）。

### H4 局外成长（依赖 server S3/S4）
- 本世结算页（评级先复用评分档位名 Q3、本世评分、奖励天赋点、选 1 遗物永久保留、重生）；天赋页（花天赋点选天赋，有上限）。

### H5 小游戏（最后，依赖 server S5）
- 转盘/答题/炼丹：前期简陋模拟界面（第一档/第二档/第三档/失败按钮），正式规则最后接。

## 6. 跨项目建议顺序与关键路径

**总体顺序**：`server S0→S1` →（并行）`admin A0/A1` + `h5 H0/H1` → `server S2` → `h5 H2` → `server S3/S4` → `admin A2/A3/A4` + `h5 H3/H4` → `server S5` + `admin/h5 小游戏`。

**最短可玩 Demo 关键路径**：`server S1→S2→S4` + `h5 H1→H2→H4`。

**第一刀建议**：从 **server S1 基础数据模型 + 配置 CRUD** 开工——无依赖、无阻塞，admin 与 h5 都引用它，做扎实后下游才有契约可接。
