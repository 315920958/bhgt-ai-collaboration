## 1. 玩家首页（p_home）

- 卷标「第一卷」、版本「v0.1 MVP · 宋式仙册」

## 2. 剧情（p_story）

**数值展示**
- 顶栏资源卡：「寿 85」「石 120」
- 书名「第一卷 · 初入仙门」
- 剧情标题「初入仙门」、节点正文（青云宗入门叙事）
- 节点标识「N001 · 青云山门」
- 选项按钮（示例）：
  - 「上前拜见长老，请求入门」
  - 「默立不语，等长老先开口」
  - 「递上引荐信函」— 标注「消耗 · 引荐函 ×1」「一次性」

**交互**
- 3 个选项按钮（点击进入下一节点）
- 按钮「查看商店」（ghost，从节点入口打开商店）

**后台规则线索（数据来源 + 判定）**
- 节点由服务端按「当前大阶段 + 当前节点 ID」推送，内容来自 `a_node` 基础配置（剧情标题/正文/图片/显示按钮数/通过后开商店）。
- **按钮筛选与随机（关键）**：服务端先过滤不满足「开启条件」的按钮（等级、基础属性、特殊属性、所需剧情道具、所需遗物、CG 条件）→ 保留「必现」按钮 → 按「随机权重」随机补足到「显示按钮数」（默认 3）→ 结果保存到服务端，**退出重进不刷新随机结果**（《Demo》12.2 / 《完整剧情设定》4.3）。
- 选项可带「消耗」（剧情道具在**点击时**才消耗）与「一次性」标记；不满足开启条件的按钮**不显示**，不用灰色锁定。
- 商店入口是否出现取决于节点「通过后开启商店」配置。

## 5. 商店 / 坊市商铺（p_shop）

**数值展示**
- 子标题「节点通关后开启」；灵石余额 120
- Tab：遗物 / 消耗品 / 剧情道具
- 商品卡（示例）：
  - 青铜古剑（稀有 · 根骨+5 战斗判定加成）价格 80
  - 聚灵玉佩（史诗 · 精怪+8 气运+3）价格 150（灵石不足置灰）
  - 护身符（凡 · 体魄+3）价格 30
  - 混元神鼎（传说 · 全属性+5）价格 500（灵石不足置灰）

**交互**
- 各商品「购买」按钮；「返回剧情」

**后台规则线索（数据来源 + 规则）**
- 商店由**节点通过后开启**，开启后展示全部已上架商品，商店本身**不单独配置**（《Demo》12.6 / 九）。
- 价格、品质、引用物品来自 `a_shop` 商品配置 → 关联 `a_item` 物品配置。
- 灵石不足不可购买；唯一遗物已拥有不可重复购买；消耗品有「每世购买上限」。
- 购买成功：扣灵石、加入物品（遗物自动生效）。

## 6. 战斗（p_battle · 玩家看到的结算态）

**数值展示**
- 子标题「节点 N012 · 妖兽巢穴」
- 结果「战斗成功」
- 结算：根骨+2、寿元-3、灵石+50、评分点数+15、获得遗物青铜古剑（稀有）、解锁 CG「妖兽巢穴 · 初探」
- 评分明细：超额属性点总和 22、评分档位「游刃有余」、档位分值 × 乘数 15 × 1.0、本次评分 +15

**交互**
- 「查看商店」「继续前行」

**后台规则线索（战斗过程 · 关键）**
- 战斗是**节点的属性**，不是独立页面；服务端按 `a_node` 战斗配置判定。
- **判定流程**（《Demo》12.3 / 《完整剧情设定》五）：
  1. 所有被配置的基础属性 ≥ 门槛 → 直接成功（不随机）。
  2. 存在不足属性 → 按**气运**生成随机补差区间，在不足属性间平均分配（向下取整，余数舍弃）。
  3. **投掷次数**决定最多连续尝试次数（默认 1），任意一次尝试补足全部不足属性即成功。
  4. 全部投掷失败 → 战斗失败。
- 玩家**只看到最终成功/失败**，不显示门槛、随机值、补差值。
- **评分计算**：Σ(各项判定属性超过门槛的数值) → 匹配评分档位（`a_battle`）→ 档位分值 × 全局评分乘数（《Demo》4.1）。使用气运补差通过时，按补差后数值算超额。评分计入本世评分点数。
- 成功/失败文案、效果、下一节点、广告（失败可看广告续命，寿元未归零时）均由节点配置；**寿元归零直接重生，不可看广告**。

## 数据模型补充约定（2026-08-05 补充，供建表 / 接口设计）

### 临时状态 = 数组存储（重要）
- 玩家的临时状态（含**负面状态**）在数据库中以**数组**形式记录，不合并成单值。
- 数组每项结构：`{ 属性, 变化值, 剩余节点数 }`。
- **叠加**：同一属性的多个临时状态**加和**（例如根骨+5 剩余3节点 与 根骨+3 剩余1节点 同时生效时为 +8）。
- **单独到期**：每个状态**独立**按自身「剩余节点数」递减，归零即移除该项，不影响其他项。
- **重生清空**：进入下一世时整个临时状态数组清空。
- 依据：《完整剧情设定》第 706 行「临时属性变化只记录属性、变化值和持续节点数，到期自动解除，重生时清空」+ 本次补充的数组/叠加/单独到期规则。

### 寿元 = 健康度（HP）
- 寿元即「健康度」，类比早期红白机的血格；战斗失败按规则扣寿元，寿元归零即重生（详见《完整剧情设定》第 4 节）。与「年龄」是两个不同概念（年龄作用目前未定，见《疑问讨论》）。

### 灵石收支（无独立公式缺口）
- 灵石收支**没有缺失的公式**：它等于所有已配置「灵石变化」字段的累加——
  - 收入：战斗成功效果（`a_node`）、阶段通关（`a_stage`）、小游戏结果档位（`a_node` 小游戏结果档位）。
  - 支出：商店购买（`a_shop`）、按钮消耗（`a_btn`）、转盘加码（小游戏结果档位的加码消耗）。
- 即「灵石余额 = 初始 + Σ收入 − Σ支出」，无需额外聚合规则。
