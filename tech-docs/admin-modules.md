# BHGT 后台管理模块梳理（基于原型导出图）

> 文档定位：给 **AI 生成代码** 与 **程序员实现** 看的后台管理模块规格。
> 依据：`界面/导出图/pages/admin/`（11 张）截图，结合 `项目文档/Demo后台管理模块与配置项.md`（权威配置项与规则）与 `项目文档/完整剧情设定及系统设定v0.0.2.md`。
> 范围：仅覆盖已有图片的模块（11 个）。玩家端模块见 `player-modules.md`。
> 每个模块含三部分：**配置字段**（页面可见字段，即后台要落库的表结构）、**交互**、**配置规则**（来自《Demo》十二节「相关规则说明」，供前后端确定校验与保存逻辑）。
> 约定：所有「ID」类字段唯一；列表页通常含搜索 + 筛选 + 「+ 新增」+ 行内编辑/删除。

## 1. 剧情节点配置（a_node）

**配置字段**
- 列表列：节点完整编号、名称、大阶段、剧情标题、战斗、按钮数、开商店、操作
- 基础配置：节点完整编号（只读，由事件编号 + 子编号自动生成）、节点名称、**所属事件（节点包）**、节点子编号、剧情标题、剧情正文、剧情图片、是否战斗节点、显示按钮数（默认 3）、通过后开启商店
- 战斗配置（仅战斗节点）：
  - 战斗数值：判定属性（勾选基础属性）、属性门槛（各项要求值）、使用气运补差（默认是）、使用投掷次数（默认是）
  - 战斗成功：成功文案、成功图片、成功效果（属性/寿元/灵石/物品/CG 变化）、成功下一节点 ID
  - 战斗失败：失败文案、失败图片、失败效果、额外寿元扣除比例（可空）、是否允许广告、广告 ID、广告后是否扣寿元、广告后是否获成功奖励、广告后下一节点 ID
- 按钮列表列：按钮 ID、文字、类型、必现、消耗、下一节点、操作

**交互**
- 搜索框 + 大阶段/类型筛选 + 搜索
- 「+ 新增节点」、行内详情/编辑

**配置规则（《Demo》六 / 12.2 / 12.3）**
- 节点必须属于一个大阶段；节点串「按钮 + 战斗 + 小游戏」。
- 节点必须属于一个「事件（节点包）」（表单新增「所属事件」下拉，选项来自 `config.nodeBundles`，2026-08-07 新增）；指定事件后其大阶段由事件自动派生，无需重复选。
- 战斗判定：所有配置基础属性 ≥ 门槛直接成功；有不足则按气运补差、投掷次数决定重试；玩家只看到成败。
- 失败可广告续命（寿元未归零时）；寿元归零直接重生。
- 显示按钮数默认 3，随机结果服务端保存、重进不刷新。

## 2. 按钮配置（a_btn）

**配置字段（四区）**
- 基础：按钮 ID、所属节点 ID、按钮文字、按钮类型（普通/小游戏）、小游戏 ID（小游戏按钮填）、是否必现、随机权重（默认 100）、下一节点 ID、是否一次性、使用后表现（隐藏/禁用）
- 开启条件：最低等级、最高等级、基础属性条件（多项）、特殊属性条件（多项）、所需剧情道具、所需遗物、CG 条件（已获得/未获得）
- 点击消耗：消耗灵石、消耗剧情道具（ID × 数量）
- 点击效果：基础属性变化、特殊属性变化、寿元变化、灵石变化、遗物变化、剧情道具变化、解锁 CG

**交互**
- 「+ 新增按钮」、行内编辑
- 列表列：按钮 ID、所属节点、文字、类型、必现、一次性、下一节点、操作

**配置规则（《Demo》七 / 12.2）**
- 按钮隶属于节点，但本身是独立配置元素；**每个按钮只能属于一个节点**，不可多节点共用。
- 节点决定展示几个按钮（默认 3）；系统先过滤不满足开启条件的按钮 → 保留必现 → 随机补足；随机权重影响出现概率。
- 不满足开启条件的按钮**不显示**（非灰锁）；剧情道具在点击时消耗；小游戏按钮携带一次性。

## 3. 属性配置（a_attr）

**配置字段**
- 列表列：属性 ID、类型、名称、说明、最小值、最大值
- 基础属性（示例）：根骨（战斗判定核心 0~999）、精怪（灵力 0~999）、魅力（交际 0~999）
- 特殊属性（示例）：气运（随机补差区间 0~100）、投掷次数（默认 1，0~10）、第三属性（待定）、悟性（待定）
- ⚠️ **寿元（HP）与灵石不是可配置战斗属性**：它们是独立**资源**（见 `database-schema.md` §6.4 的 `hp` / `maxHp` / `hpInit` / `spiritStones`），**不进入 `config.attributes` 表**。此前误将「体魄（寿元）」「财富（灵石）」列为基础属性，现已纠正；其初始值由「开局配置」的「初始寿元 / 初始灵石」单独设定，不写入属性表。
- 表单：属性 ID、类型（基础/特殊）、名称、说明、最小值、最大值

**交互**
- Tab（全部/基础/特殊）、「+ 新增属性」、编辑/删除

**配置规则（《Demo》一 / 12.1）**
- 基础属性与特殊属性**同一张配置表**，用「类型」区分。
- 气运决定随机补差区间；投掷次数影响战斗判定（默认 1，任意一次投掷通过即成功）。
- 第三个特殊属性与悟性用途**待定**。

## 4. 天赋配置（a_talent）

**配置字段（多 Tab）**
- 天赋列表：天赋 ID、名称、品质、说明、效果、消耗点数
- 品质配置：品质 ID、品质名称、显示颜色、所需天赋点（凡 1 / 稀有 2 / 史诗 3 / 传说 5）
- 开局配置：初始寿元 100、初始灵石 100、初始等级 1、初始天赋点 5、初始可选数 3；初始基础属性 根骨30/精怪30/魅力30（寿元、灵石为资源，不在此列，见上注）
- 通关评分档位：档位 ID、档位名称、评分范围、奖励天赋点
- 可选数量上限：累计通关次数、可选天赋数量上限

**交互**
- 各 Tab 内编辑（天赋列表 / 品质 / 开局 / 通关评分档位 / 可选数量上限）

**配置规则（《Demo》二 / 12.9）**
- 品质名称与颜色**不写死**，由后台配置；不同品质可配不同天赋点消耗。
- 开局初值集中在此配置；可选天赋数量随累计通关次数提高（上限由配置决定）。
- 评分点与天赋点是两种资源；评分档位奖励天赋点，评分点本身不能选天赋。

## 5. 境界配置（a_realm）

**配置字段**
- 列表列：等级（数字）、境界名称、说明、突破寿元增加、可分配属性点、单项上限
- 示例：1 炼气一层 +10；3 炼气三层 +10 / 3 点 / 上限 2；4 筑基初期 +20 / 5 / 3；6 金丹初期 +30 / 8 / 4

**交互**
- 「+ 新增境界」、编辑

**配置规则（《Demo》三 / 《完整剧情设定》三）**
- 等级按数字顺序提升，不通过经验值；境界突破与大阶段通关是两套独立机制。
- 突破寿元增加可固定值或随机区间（如 10~20）；可分配属性点留空=不分配；突破可发属性点 + 单项上限。
- 突破按钮结算后立即失效（本世不可再点）；突破失败按普通战斗节点失败规则处理。

## 6. 关卡（大阶段）配置（a_stage）

**配置字段**
- 列表列：阶段 ID、名称、顺序、最后节点、通关寿元、下一阶段、通关文案、操作
- 示例：stage_01 初入仙门 / 1 / N020 / 回满 / stage_02；stage_02 筑基之劫 / 2 / N045 / 固定+30
- 通关效果配置：阶段名称、通关寿元处理（不恢复 / 固定恢复 / 回满）、通关效果（灵石+100 评分+20）、通关文案、通关图片

**交互**
- 编辑（阶段为顺序结构，非简单列表增删需谨慎）

**配置规则（《Demo》五 / 《完整剧情设定》4.1）**
- 阶段按「顺序 + 最后节点 + 下一阶段」串联推进。
- 通关寿元三种处理；每个大阶段最后一个节点固定为**阶段通关小游戏节点**。
- 大阶段通关 ≠ 境界突破。

## 7. 商品配置（a_shop）

**配置字段**
- 列表列：商品 ID、类型、引用物品、灵石价格、上架、重复购买、每世上限、操作
- 示例：shop_01 遗物/青铜古剑/80/是/否/—；shop_04 消耗品/回春丹/20/是/是/3；shop_05 剧情道具/引荐函/50/是/否/1

**交互**
- 行内编辑上下架、价格、重复购买、每世上限

**配置规则（《Demo》九 / 12.6）**
- 商品**引用物品表**（遗物/消耗品/剧情道具），不直接定义属性；遗物商品引遗物 ID，消耗品引消耗品 ID + 每世上限，剧情道具直接引 ID。
- 商店本身不配置：节点通关展示全部**已上架**商品。
- 灵石不足不可买；唯一遗物已拥有不可重复买；消耗品每世上限生效。

## 8. 物品配置（a_item）

**配置字段（三类列表）**
- 遗物列表：ID、名称、品质、属性加成、允许购买、节点奖励、永久保留
  - 示例：rel_01 凡骨之心/凡/魅力+5/可买/节点奖励/否；rel_02 青铜古剑/稀有/根骨+5/可买/奖励/是(永久)
- 消耗品列表：ID、名称、属性变化、临时持续、每次消耗、最大持有
  - 示例：con_01 回春丹/寿元+10/—/1/5；con_02 灵露/根骨+3/3 节点/1/3
- 剧情道具列表：ID、名称、说明、允许购买、节点奖励、最大持有
  - 示例：plot_01 引荐函/凭证/可买/奖励/1

**交互**
- 三类列表分别编辑

**配置规则（《Demo》八 / 12.5）**
- 遗物：允许购买 / 节点奖励 / 永久保留三态可配；获后自动生效、只给固定数值（不用百分比）、不可重复获得、不可出售。
- 消耗品：只能购买（不能节点奖励）；使用后消失、重生清空；可配「使用条件」「每次消耗数量」「最大持有」。
- 剧情道具：可购买或节点奖励；使用条件/消耗/结果在**按钮配置**中定义。

## 9. CG 配置（a_cg）

**配置字段**
- 列表列：CG ID、名称、缩略图、原图、占位图、回看剧情、操作
- 表单：CG 名称、缩略图、CG 原图、未解锁占位图、回看剧情文字
- 示例：cg_01~cg_03 已配图；cg_04 筑基天劫、cg_05 金丹大成 未配（—）

**交互**
- 行内编辑图片与回看文案

**配置规则（《Demo》十 / 12.7）**
- CG 永久保留、图鉴回看；需配置**未解锁占位图**与回看剧情文字。
- 解锁来源由节点 / 战斗 / 小游戏结果触发；重复遇到不重复入库、不转其他奖励，路线不关闭。

## 10. 广告配置（a_ad）

**配置字段**
- 列表列：广告 ID、广告图片、引用位置、操作
- 表单：广告 ID、广告图片、保存
- 示例：ad_01 复活广告.png / 战斗失败·N012；ad_02 双倍奖励.png / 小游戏·灵力转盘；ad_03 减少惩罚.png / 小游戏·丹药炼制

**交互**
- 行内编辑图片

**配置规则（《Demo》十一 / 12 广告）**
- 广告本身**只配图片与引用位置**；广告完成后的具体效果（复活 / 双倍 / 减惩）由节点 / 战斗 / 小游戏的结果档位配置，**不在本页**。
- Demo 阶段用模拟广告按钮；真实 TapTap 广告接入待后续调研。

## 11. 战斗（评分）配置（a_battle）

**配置字段**
- 全局配置：评分乘数（示例 1.0，档位分值统一乘以它）
- 评分档位列：档位 ID、档位名称、超额属性点总和下限、超额属性点总和上限、档位分值
  - 示例：bs_01 险胜 0~5 /5；bs_02 游刃有余 6~15 /10；bs_03 轻松取胜 16~30 /15；bs_04 碾压 31~999 /25

**交互**
- 编辑档位（数量可配）

**配置规则（《Demo》四 / 12.3）**
- 战斗评分采用**全局统一规则**，不在每个战斗节点重复配置。
- 计算：Σ(各项判定属性超过门槛的数值) → 匹配档位 → 档位分值 × 全局乘数 = 本次战斗评分。
- 使用气运补差通过时，按补差后最终判定数值计算超额。
- 评分档位数量可配；门槛/属性来自 `a_node` 战斗配置。

## 12. 节点包（事件）配置（a_node_bundle · 2026-08-07 新增）

> 三层结构中间层：**大阶段(stage) → 节点包(nodeBundle) → 剧情节点(node)**。
> ⚠️ **双层命名**：代码 / 数据层称「节点包(nodeBundle)」；**admin 用户可见文案统一显示「事件」**（菜单、标题、按钮、列名、表单标签），仅为展示别名，代码标识符不变。

**配置字段**
- 列表列：事件 ID（节点包 code）、名称、所属大阶段、说明、操作
- 表单：事件 ID（code，唯一）、事件名称、所属大阶段、说明

**交互**
- 列表（可按大阶段筛选）+ 「+ 新增事件」+ 行内编辑 / 删除；`code` 允许编辑（保存时校验唯一）

**配置规则（《事件模块》约定）**
- 一个节点包隶属一个阶段，内部是一组「殊途同归」的剧情节点；节点通过「所属事件」下拉挂到节点包下（见 §1）。
- 节点包**不存**入口 / 出口 / 图形坐标等字段（2026-08-06 删除）；入口 / 出口由事件内节点的按钮指向动态推导（见下「事件视图」）。

**事件视图（路径图 · 2026-08-07 新增）**
- 两层 SVG 图，辅助排查剧情连通性：
  - **事件级路径图**：拉取全部事件，画「事件 → 事件」有向边；标注每个事件的入口 / 出口节点 `code`，`isNormal=false` 的事件（缺入口或出口）高亮提示。
  - **单事件内节点图**：画本事件内节点 + 按钮指向；点击节点可钻取编辑；标注跨事件出边（指向其他事件节点）。
- 入口 = 本事件内无本事件按钮指向的节点；出口 = 有按钮指向非本事件节点的节点。
- 口径以服务端 `GET /api/admin/node-bundles/graph` 与 `GET /api/admin/node-bundles/:code/nodes` 为准（见 `api/admin-api.md` §16.2）。

## 附：后台配置间的引用关系（供建表/接口设计）
- `a_node`（节点）→ 引用 `a_btn`（按钮）、`a_attr`（判定属性）、`a_battle`（评分档位）、`a_cg`/`a_item`/`a_ad`（效果与广告）
- `a_btn`（按钮）→ 引用 `a_attr`（开启条件属性）、`a_item`（消耗/奖励物品）、`a_cg`（解锁）
- `a_shop`（商品）→ 引用 `a_item`（遗物/消耗品/剧情道具）
- `a_talent`（天赋/品质/开局/评分档位/可选上限）→ 驱动玩家开局与局外成长
- `a_realm`（境界）→ 驱动突破奖励
- `a_stage`（大阶段）→ 串联节点流与通关处理
- `a_cg` / `a_ad` → 被节点、战斗、小游戏结果引用
- `a_node_bundle`（事件 / 节点包）→ 中间层，串联 stage 与 node；驱动事件视图

> 说明：以上 11 个模块均基于现有导出图；项目文档中描述但暂无原型图的配置（如独立的「地图/阶段切换过渡页」「突破小游戏独立配置页」）不在本文档范围。

## 补充约定（2026-08-05 补充）

### 气运 → 补差区间（从简原则）
- 气运补差逻辑**从简**：后台配置「气运值（0~100）」，直接对应补差区间上限，即 `补差区间 = [0, 气运值]`（示意）。
- 具体映射（是否线性、是否取整、是否分档）后续确认，但原则保持简单，不引入复杂曲线。
- 气运值由 `a_attr` 特殊属性配置，战斗判定时在不足属性间平均分配补差（向下取整，余数舍弃）。

### 按钮加权随机补足（归属节点 + 按钮模块）
- 「按随机权重随机补足显示按钮」属于**节点 + 按钮模块**的逻辑（配置在 `a_btn` 的随机权重、`a_node` 的显示按钮数），不单列模块。
- 流程：过滤不满足开启条件的按钮 → 保留「必现」按钮 → 按权重随机补足到显示按钮数；随机结果服务端保存、重进不刷新。
- 权重影响出现概率；必现按钮优先占位；是否允许同一按钮重复出现待定（疑问项）。
