# 原型图与样式定义说明

## 1. 第一批原型图样式定义

- 目录：`界面/原型图/第一批原型图样式定义/`
- 这里以 **HTML 文件** 的方式定义了整个产品的视觉样式——**字体、颜色、字号、间距、组件等设计令牌**，全部集中在 `design-tokens.css`，并由 `ds.html`（设计系统总览）统一展示。
- 页面清单：
  - `ds.html`：设计规范总览（设计系统）
  - `pages/player/`：玩家端 9 页（首页 / 剧情 / 角色 / 背包 / 商店 / 战斗 / 结算 / 天赋 / CG）
  - `pages/admin/`：后台管理 11 页（节点 / 按钮 / 属性 / 天赋 / 境界 / 关卡 / 商品 / 物品 / CG / 广告 / 战斗）
  - `pages/minigame/`：小游戏 3 页（转盘 / 答题 / 炼丹）
- 设计语言：宋式仙册 Design System V1——宋代美学（古籍 / 玉器 / 山水 / 书法），克制雅致；无渐变、无发光、无强阴影、统一宣纸底。配色为 5 个核心色 + 品质色 + 数值色；字体标题用书法体、正文用宋体。

## 2. 为什么用 HTML 原型而不是 Figma（.fig）

- 制作 `.fig` 文件工作量大，而本项目是**小项目**，用 HTML 原型就足以满足「看效果、对齐视觉、指导开发」的沟通需求。
- HTML 原型轻量，直接用浏览器打开即可查看，也方便 AI 读源码理解 DOM 结构与样式，比 fig 更契合本项目的协作节奏。

## 3. 导出图（供 AI 写代码时查看）

- 目录：`界面/导出图/`
- 用途：放置**便于 AI 写代码时查看的参考图片**（由原型 HTML 截图生成）。
- 规格：
  - 玩家端 / 小游戏：`375 × 667`（手机模式一屏）
  - 后台管理：`1440` 宽整页（电脑浏览大小，含右侧功能界面；左侧菜单在代码层 `bhgt-admin` 的 MainLayout 中实现，不在截图里）
- 生成方式：在沙箱用系统已安装的 Google Chrome 经 Playwright 驱动截图。
- 已知限制：截图环境无法访问 Google Fonts，标题书法体会回退为系统楷体 / 宋体，布局与配色不受影响。

## 4. 给协作者 / AI 的提示

- 看视觉与样式 → 打开 `界面/原型图/第一批原型图样式定义/` 下的 HTML（推荐先看 `ds.html` 与 `design-tokens.css`）。
- AI 写前端时 → 参考 `界面/导出图/` 的截图对齐布局，参考 `design-tokens.css` 对齐设计令牌（颜色、字号、间距、组件类名）。

## 5. 补充约定（2026-08-05 补充）

### 5.1 后台管理界面原则：给自己人看，可简约
- 后台管理是**内部使用**工具，不面向玩家，界面可以**简约**，不必追求华丽视觉。
- 据此新增了「游戏基本信息配置」页（`pages/admin/a_gameinfo.html`，导出图 `pages/admin/a_gameinfo.png`）：仅含游戏名 / 副标题 / 版本号 / 新游戏默认值，结构极简，作为后续后台「游戏信息配置」模块的原型。

### 5.2 阶段即卷
- 玩家在剧情页看到的「第 N 卷 · 阶段名」中，**「卷」就是大阶段（stage）本身**，由大阶段顺序自动生成（第 1 阶段 = 第一卷），**不单独配置卷名**。阶段名由 `a_stage` 配置。

### 5.3 小游戏高度解耦 + 开发顺序
- 小游戏（转盘 / 答题 / 炼丹）应视为**高度解耦的外部模块**：最终的「结果档位值」由小游戏自身提供，主游戏只消费其结果（寿元 / 属性 / 灵石 / 评分 / 遗物 / CG / 广告）。
- **开发顺序**：小游戏属于**最后开发**的内容。前期自体验阶段用**非常简陋的模拟界面**即可——界面上摆几个按钮（如「第一档 / 第二档 / 第三档 / 失败」），点哪个直接给对应结果，不必实现真实玩法。正式的小游戏配置模块细节后续再议。
- **炼丹**是三种小游戏之一（与转盘、答题并列），其「灵材」为小游戏内部输入，**不进物品配置**（不存在独立的「炼丹道具」品类）。

### 5.4 玩家端新增白描原型
- 新增「开始新游戏 · 填写昵称 + 选择性别」白描页（`pages/player/p_create.html`，导出图 `pages/player/p_create.png`）。年龄字段因作用未定暂留空（疑问项，见《疑问讨论》文档）。
