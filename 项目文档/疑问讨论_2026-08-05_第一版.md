### Q7. 按钮「随机权重」怎么转概率？（讨论记录，未最终拍板）
- 节点展示 N 个按钮时，不满足条件的被过滤，剩下的按「随机权重」随机补足。
- 用户与朋友的**讨论原文记录**：
  - 朋友可能想要一个「权重 → 对应概率」的公式；
  - 用户倾向：**直接把所有候选按钮的权重加和，再按每个按钮的权重占比得到它被摇中的概率**（即「权重轮盘赌」：概率 = 该按钮权重 / 全部候选权重之和）。
- 当前处理：**先按「权重占比 = 权重 / 总权重」实现**（轮盘赌），待用户与朋友确认是否就用这个；不阻塞开发（dev-plan S2 已用此默认值）。
- 归属：这是「节点 + 按钮」模块的逻辑，不单独建模块。

## ✅ 已确认 / 非疑问（本轮拍板）

- **境界突破在小游戏里**：采用小游戏形式（设定第 8 节已确认）。

- **灵石收支无公式缺口**：= 所有已配置「灵石变化」字段的累加。
- **临时状态 = 数组存储**：每项 {属性, 变化值, 剩余节点数}，叠加、单独到期、重生清空（已写入 `tech-docs/player-modules.md`）。

- **本世评分仅由「战斗」+「小游戏」产生**：普通剧情事件节点（选项按钮）不加不减本世评分（已澄清 2026-08-05）。

### Q1（已确认）角色页不要进度条
- 结论：**不显示境界进度条**。境界按数字等级顺序提升，不做 1200/3000 这类进度展示。
- 影响：h5 角色页不画进度条（dev-plan H1 的「进度条先占位」已去除）。

### Q2（已确认）需要做一个「分配属性点」界面
- 结论：突破成功发放的「可分配属性点」目前没有入口，需要**单独做一个「分配属性点」界面**（可放在角色页或突破结算后）。
- 技术约定：每种属性点需有**独立字段**记录，使用时是**加权值**（与 Q14 一致）。

### Q3（已确认）做一套「评分标准」配置，可先空着占位
- 结论：本世结算的「评级」（如「仙缘深厚」）需要一条「评分标准 → 评级文字」的映射规则；**先建这个评分标准配置，内容可以先空着占位**，后续再填。
- 影响：新增一个评分标准配置项（后台 + server 落库），前期空配置不影响开发。

### Q4（已确认）普通节点不加评分，且无扣分，只有正向分
- 结论：普通剧情事件节点（选项按钮）不影响本世评分；评分仅来自战斗 + 小游戏，**且只有正向加分、没有扣分项**。
- 影响：「按钮配置」不建「本世评分变化」字段；评分明细里不出现「事件扣分」。

### Q5（已确认）不套用转盘「加码」规则
- 结论：转盘「加码（消耗 30 灵石，提升 1 档）」**不套用**——和之前定的小游戏简化要求不符，去掉加码规则。
- 影响：小游戏前期一律简陋模拟，不接加码数值。

### Q9（已确认）年龄规则：从 0 岁开始，每过一回合 +1 岁，固定
- 结论：年龄**固定规则**——新建角色时从 **0 岁**开始，**每过一回合（一个节点）自动 +1 岁**。不是过特定节点才长，是每回合都长，固定递增。
- 影响：h5 创建角色不填年龄（从 0 起）；角色页年龄 = 已走过回合数；dev-plan H1 的「年龄留空/写死 18」已改为「0 起、每回合 +1、固定」。
