# 项目结构与职责说明

> 本文档说明本产品涉及的全部仓库及其职责。写法与同目录其他文档保持一致，供开发、运营与 AI 协作参考。

## 一、总览

本产品共涉及 **5 个仓库**，其中 **4 个为代码工程**（实际编写、运行业务代码），另外 **1 个为 AI 协作文档仓库**（不放代码）。

### 1. 四个代码工程

> **命名约定（2026-08-14 更新）**：玩家端现有两个独立代码工程：`bhgt-h5-client` 是 React + Vite 的 TapTap H5 包主线；`bhgt-cocos-client` 是 Cocos Creator 的 TapTap 小游戏实现/技术验证工程。两者拥有各自独立的 Git 远程仓库与 `develop` 分支，不能再视为同一个项目或互相替换。后续提到“代码工程”默认指下列四个仓库，不含 AI 协作文档仓库。

| 仓库 | 定位 | 是否代码工程 | 远程仓库 | 分支 |
| --- | --- | --- | --- | --- |
| **bhgt-h5-client** | H5 玩家端（当前 TapTap H5 包主线） | ✅ 是 | `git@github.com:315920958/bhgt-h5-client.git` | `develop` |
| **bhgt-cocos-client** | Cocos 玩家端（TapTap 小游戏实现 / 技术验证） | ✅ 是 | `git@github.com:315920958/bhgt-cocos-client.git` | `develop` |
| **bhgt-admin** | 后台管理端（运营 / 管理员） | ✅ 是 | `git@github.com:315920958/bhgt-admin.git` | `develop` |
| **bhgt-server** | 服务端（后端 API） | ✅ 是 | `git@github.com:315920958/bhgt-server.git` | `develop` |

### 2. 一个 AI 协作文档仓库（非代码工程）

| 仓库 | 定位 | 是否代码工程 | 远程仓库 | 分支 |
| --- | --- | --- | --- | --- |
| **bhgt-ai-collaboration** | AI 协作与文档仓库（本文档所在仓库） | ❌ 否 | `git@github.com:315920958/bhgt-ai-collaboration.git` | `main` |

**架构关系：**

- `bhgt-h5-client`、`bhgt-cocos-client` 与 `bhgt-admin` 都通过 HTTP 调用 `bhgt-server`；
- `bhgt-server` 统一接 MongoDB 存取数据；
- `bhgt-ai-collaboration` 不放代码，只放需求文档、原型图、AI 协作指令与自定义技能。

## 二、bhgt-h5-client（H5 用户端 / 当前玩家端主线）

| 项 | 说明 |
| --- | --- |
| 角色 | 面向终端玩家的 React H5 游戏客户端 |
| 终端优先级 | **手机端优先**：以手机竖屏、触摸操作和 TapTap H5 容器为主要目标；桌面浏览器用于开发预览与辅助调试 |
| 现状 | 当前 TapTap H5 包主线；已恢复 React + Vite 实现，并验证容器可注入 `tap` 对象、调用 `tap.login()` 返回 code |
| 已配置 | 统一 API 请求层、登录态存储、TapTap H5 容器登录、普通浏览器扫码登录、vConsole（开发环境）、角色初始化与节点入口 |
| 技术栈 | React + Vite + TypeScript；构建产物为 `dist/`，可通过 MCP 或网页后台上传为 H5 包 |
| 作用 | 玩家在此进行游戏（登录、创建角色、剧情、战斗、商店、重生等）；通过接口调用 `bhgt-server` 获取数据、保存存档 |
| 远程仓库 | `git@github.com:315920958/bhgt-h5-client.git` |
| 当前分支 | `develop`（另含 test / production 分支） |

### 界面相关素材目录

本仓库除 `项目文档/` 外，另设 `界面/` 目录，集中存放游戏 UI 相关的视觉素材（**不放代码**，仅放图片 / 设计资源）：

| 目录 | 用途 |
| --- | --- |
| `界面/原型图` | **UI 原型 / 线框图**。设计阶段产出的界面草图、交互原型（一般是 Figma / 墨刀等工具导出的原型截图），用于评审玩法流程与页面布局 |
| `界面/导出图` | **设计终稿导出图**。从设计工具导出的成品素材——最终界面图、切图、图标等，供开发对照或运营展示 |

> 说明：`界面/` 下两个子目录当前以 `.gitkeep` 占位保留结构，待放入真实图片素材后再提交。

## 七、端口与通讯约定

| 服务 | 端口 | 说明 |
| --- | --- | --- |
| bhgt-admin | 4000 | 前端开发服务器；`/api` 经 Vite 代理转发到 4001 |
| bhgt-h5-client | Vite 默认 5173 | H5 开发服务器；API 地址从 `.env.development.local`（存在时优先）读取 |
| bhgt-cocos-client | — | Cocos Creator 本地预览 / TapTap 小游戏调试工具 |
| bhgt-server | 4001 | 后端 API；对外统一前缀 `/api`，已开启 CORS |

> 前后端通讯方式：`bhgt-admin`、H5 玩家端和 Cocos 玩家端均通过统一 API 调用 `bhgt-server`；H5 地址由 Vite 环境文件注入，Cocos 地址由其运行时配置注入。

## 八、分支策略约定

**适用范围**：四个代码工程 `bhgt-h5-client`、`bhgt-cocos-client`、`bhgt-admin`、`bhgt-server`。文档仓库 `bhgt-ai-collaboration` 不参与此分支模型，仅用 `main`。

四个代码工程统一采用分支模型：日常开发使用 `develop`，测试使用 `test`，线上使用 `production`；历史分支以各仓库实际存在情况为准。

| 分支 | 角色 | 说明 |
| --- | --- | --- |
| `develop` | 开发分支 | 日常开发基线；当前**本地默认所在分支**，已推送到服务端 |
| `test` | 测试分支 | 测试环境部署与自测包所对应的代码分支 |
| `production` | 生产分支 | 线上稳定版本分支 |

> 说明：各仓库可能保留 `main` 或其他历史分支；以远程仓库实际分支为准，不再把 `release` 作为统一强制分支。
